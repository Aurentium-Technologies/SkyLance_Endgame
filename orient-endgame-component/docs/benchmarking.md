# Reproducible strength experiments

Orient has no demonstrated 3000 rating yet. The target is a local estimate anchored to a frozen CCRL Blitz list; it is not an official CCRL rating or a human FIDE rating. All external engines are benchmark opponents only. Their code, evaluation weights, moves, search scores and training labels are excluded from Orient development and training.

Python tooling uses only the standard library. The engine and Fastchess paths in saved manifests are absolute. Outputs are created in new directories and never appended to an earlier campaign.

## Development loop

1. Build and test Orient, then freeze its baseline binary and source archive with `tools/checkpoint.py`. Keep a checkpoint for each candidate, including its compiler, configuration and correctness evidence.
2. Generate legal opening corpora from Orient's own move generator. The generator uses uniformly sampled legal moves without evaluations, games or labels from another engine. Save the seed, generator and Orient binary hashes. Use separate development, confirmation and holdout sets; never inspect holdout results while tuning.
3. Compare a candidate with the frozen baseline at `10+0.1` using reversed opening pairs, SPRT `[0,5]` normalized Elo, 5% errors and at most 20,000 games. Confirm accepted candidates at `60+0.6` under the same stopping rule. Rejected or capped tests do not establish an improvement.
4. Keep complete PGNs, logs and both positive and negative experiments. A speed gain, tactical score or short pilot is insufficient to claim the final rating target.

For example, from the project root:

```sh
python3 tools/openings.py --engine build/release/orient --development 10000 --confirmation 10000 --holdout 3000 --out artifacts/openings/v1
python3 tools/calibrate_sprt.py --binary build/native/orient-sprt-calibration --trials 1000 --seed 2026102402 --out artifacts/statistics/paired-calibration-001
python3 tools/matches.py dev --candidate artifacts/checkpoints/candidate/orient --baseline artifacts/checkpoints/baseline/orient --fastchess external/tools/fastchess-v1.8.2-alpha/fastchess --development artifacts/openings/v1/development.epd --confirmation artifacts/openings/v1/confirmation.epd --sprt-calibration artifacts/statistics/paired-calibration-001/result.json --out artifacts/matches/experiment-001
```

Set individual candidate or baseline UCI options with repeatable flags such as `--candidate-option "Late Move Reductions=true" --baseline-option "Late Move Reductions=false"`. The option names must match the engine's actual UCI handshake. Each match uses one search thread, no pondering, and at most three concurrent games. `-repeat` and `-games 2` declare the reversed opening pairs explicitly. Fastchess's working directory is the individual run directory so its saved configuration does not overwrite project files.

The controller runs fixed batches of 32 complete opening pairs, then evaluates
the SPRT. It does not ask Fastchess to stop individual games on an SPRT decision:
that previously left unmatched games under concurrent play. Every batch must
finish and pass its PGN/reliability audit before contributing to a decision.
Each stage needs 10,000 unique openings so the 20,000-game cap never wraps the
book. Raw batch PGNs, annotations, commands and logs are preserved; a separate
aggregate PGN changes only Round headers to global pair numbers. A crash,
forfeit or other fatal runner diagnostic stops development immediately and
invalidates the experiment. Final fixed-sample validation retains its separate
full-sample protocol.

`tools/sprt.py` independently implements the constrained multinomial likelihood
for normalized Elo described in Michel Van den Bergh's
[practical note, section 4.1](https://cantate.be/Fishtest/normalized_elo_practical.pdf).
The five outcomes are opening-pair average scores, and both fits use the same
complete pairs. The declared hypotheses remain `[0,5]` nElo with nominal 5%
errors; the controller checks boundaries only between batches. Numerical fit
failures reject the evidence. Zero-count-bin regularization and the conservative
zero-variance behavior are recorded in each statistics result.

Before real development play, `--sprt-calibration` requires a successful frozen
calibration for the exact calculator source and test settings. Saved calibration
001 crosschecks 55 Python/C++ fits and simulates 1,000 trials at each hypothesis
for three pair distributions. No numerical failures occurred; wrong-decision
rates were 1.6–3.3%, with every Wilson 95% upper endpoint below 5%. These finite
IID examples do not prove universal error control, and their synthetic trials
are not chess games or rating evidence. Recalibrate after calculator changes.

The actual expanded corpora are `artifacts/openings/research-v2/`: 10,000 fresh
development positions and 10,000 fresh confirmation positions, generated by the
original rule-only C++ sampler. The frozen manifest is `corpora-frozen.json`.
Both sets exclude all original research-v1 positions, including the unchanged
3,000-position final holdout, using the stricter training feature equivalence.
The original holdout file and hash remain unchanged. The expansion records its
producer source, executable, commands and seeds. Use this manifest for new
training ancestry; an older network tied to a different corpus identity requires
a new own-data training/export campaign before adoption with the expanded set.

For unattended Linux runs, wrap the whole controller with
`systemd-inhibit --what=sleep:idle:handle-lid-switch --mode=block --who=Orient --why='Orient local match experiment'`.
This holds a process-scoped sleep lock and releases it on exit. Save that outer
launcher command as evidence as well as the runner commands. Current clock
smokes use `Move Overhead=50` on both Orient configurations; a smoke establishes
local reliability only, not a strength gain.

Uniform legal openings are reproducible but often unbalanced or unlike human opening play. Colour reversal reduces colour/opening bias; it does not establish equivalence to CCRL's own opening distribution. The final report must retain this limitation.

The generator removes en-passant fields when Orient confirms that no legal en-passant capture exists. This keeps equivalent chess positions from being treated as different openings, and matches Fastchess's FEN normalization. Exclude previously used pilot corpora with repeatable `--exclude path/to/corpus.epd` flags; their hashes are recorded in the corpus manifest.

## Independent opponent selection

The saved HTML `external/downloads/ccrl-blitz-2026-10-23.html` is a real CCRL Blitz snapshot headed October 17, 2026. `benchmarks/ccrl-shortlist-2026-10-23.json` is parsed from that snapshot. It is a **shortlist**, not a verified final opponent selection.

```sh
python3 tools/select_opponents.py --snapshot external/downloads/ccrl-blitz-2026-10-23.html --out artifacts/shortlist.json
```

The parser excludes multi-CPU, non-OSS-labelled, under-500-game and exactly-3000 rows. The OSS label alone does not prove a licence or downloadable Linux binary. Review the engine author's exact release assets, explicit licence, version identity and lineage without reading engine source. Put reviewed releases in a JSON array whose records contain:

- `name`: the exact snapshot name, including architecture and version;
- `family`, `version`, `source_url`, `release_url`, `license`, `license_url`;
- `author_linux_release_verified: true`, set only after verifying the exact author's Linux asset.

Retain evidence and reasons when closer candidates have no eligible release; do not selectively omit closer eligible versions. `release_url` identifies the exact author asset, and each eventual binary is hashed separately. Select three independent families below and three above 3000, ordered by distance from 3000, descending published game count, then name. Do not use two versions of one family, including forks treated as the same lineage.

Before freezing a campaign, each selected release also needs `binary`,
`license_artifact` and `uci_probe` artifact records. The saved probe must include
its binary hash, successful UCI output and advertised option names. Certification
binds the actual opponent executable to that selected author binary's hash, checks
the licence/probe evidence, and requires an advertised Hash range accepting 256.
Matching release names and URLs alone do not establish that binding.

```sh
python3 tools/select_opponents.py --snapshot external/downloads/ccrl-blitz-2026-10-23.html --catalogue artifacts/reviewed-releases.json --out artifacts/opponent-selection.json
```

The selector errors when six reviewed independent families are unavailable, or when a nearer eligible snapshot entry has not been reviewed. The catalogue may be an object with `eligible` release records and `excluded` records containing an exact snapshot `name`, a `reason`, and author/licence `evidence_urls`. Every omitted entry nearer than the chosen cutoff needs such evidence. No current engine is incorporated into Orient by this process. Keep third-party licences with externally downloaded opponents; Orient's MIT licence covers Orient, not those binaries.

## Freeze and run the certification campaign

Prepare a JSON spec with `candidate` and six `opponents`. Each engine has `name`, `path` and `options`; candidate also has `checkpoint: {"path": "/absolute/path/checkpoint.json", "sha256": "..."}` from the checkpoint tool. Opponents additionally use the selected `family`, `version`, `source_url`, `release_url`, `license`, `rating_source_url`, `rating`, `rating_error_95` and `rating_games`. Use `rating_name` only if the PGN engine name differs from the exact CCRL name. Store any author metadata evidence beside the spec.

The freeze tool probes UCI options, enforces Hash=256 MiB and Threads=1, records Ponder=false, and omits unsupported Ponder/Threads commands for engines which do not expose them. The runner never issues `go ponder`. Hash must be supported. Freeze verifies source/checkpoint hashes, the exact saved reference rows, selection provenance, and disjoint opening corpora before producing the manifest. Record hardware calibration and any CCRL hardware differences in the spec's `hardware_calibration` field.

```sh
python3 tools/freeze.py --spec artifacts/opponents-spec.json --fastchess external/tools/fastchess-v1.8.2-alpha/fastchess --holdout artifacts/openings/v1/holdout.epd --corpora artifacts/openings/v1/corpora.json --snapshot external/downloads/ccrl-blitz-2026-10-23.html --selection artifacts/opponent-selection.json --out artifacts/campaign-manifest.json
python3 tools/matches.py certify --manifest artifacts/campaign-manifest.json --out artifacts/certification-001
python3 tools/rating.py --manifest artifacts/campaign-manifest.json --campaign artifacts/certification-001 --out artifacts/certification-001/report.json
```

Certification always plays 6,000 games, 1,000 per opponent, at `120+1`, with one search thread, 256 MiB hash and pondering disabled. Each opponent receives 500 distinct openings, each played in both colours. The frozen 3,000-opening holdout is partitioned into six nonoverlapping slices. There is no SPRT, strength-based early stop, resignation adjudication or evaluation-based draw adjudication. The 500-move safety cap invalidates a run if reached. Candidate reliability failures invalidate certification even if the score is high. Interrupted/incomplete campaigns remain evidence but cannot certify the target; preserve them and begin any later campaign under a fresh manifest and directory.

The local computer is the only compute resource. Never run more than three concurrent games across all experiments or more than four training threads. Do not run multiple match controllers concurrently if their combined games would exceed this cap.

The shared compute guard follows the controller and designated heavy child
processes. Match runners, own self-players, benchmarks and calibration children
inherit its open file description. If a controller exits before its child work
ends, that child retains the kernel lock; a new controller cannot silently
overlap it. The lock is released after the last owning descriptor closes.
Worker threads use the same process-wide guard registry. The JSON owner/time
in `compute.lock` is informational; the kernel lock and live process state are
the authority. Synthetic crash tests use separate temporary lock files and
sleeping/fake subprocesses, with no actual match games.

`tools/calibrate.py --checkpoint path/to/checkpoint.json --out new/calibration`
records repeated own-engine fixed-depth workloads sequentially and in three-process
waves under the compute lease. It preserves exact work signatures and timings.
This describes local throughput and contention; it provides no direct calibration
to CCRL reference hardware and supplies no rating conversion. Preserve variability
and this limitation in any final campaign report.

### Timing search changes

Wait until the shared compute lease is free and stop other CPU workloads before
measuring timing. The controller refuses to overlap a timing experiment with a
tournament or training campaign. For a change intended to execute identical
search work faster, use the default fixed-work comparison:

```sh
python3 tools/performance.py --baseline artifacts/checkpoints/orient-010-hash-hints/orient --candidate artifacts/checkpoints/orient-010-hash-hints/orient --candidate-argument=--fast-quiescence --depth 6 --pairs 10 --out artifacts/performance/fast-quiescence-001
```

That mode requires identical moves, scores and node counts. Move ordering can
change the searched tree, so measure its time to a fixed depth instead:

```sh
python3 tools/performance.py --baseline artifacts/checkpoints/orient-010-hash-hints/orient --candidate artifacts/checkpoints/orient-010-hash-hints/orient --candidate-argument=--hash-move-hints --comparison fixed-depth --depth 6 --pairs 10 --out artifacts/performance/hash-hints-001
```

Fixed-depth mode requires the same numerical score on each of the three own
benchmark positions. Moves may differ when scores tie, and node counts may
change. Each engine must repeat its own complete move/score/node signature on
every sample; inconsistent work or unequal scores fails the measurement and
preserves raw evidence. These checks cover the declared workload, not every
chess position. Both modes alternate execution order, preserve raw commands and
responses, freeze the measurement/helper sources and recheck artifact hashes.
The report distinguishes identical work from time to equal-score fixed depth,
and records both node totals. Its completion-time ratio is not an NPS comparison
when work differs.

These CLI bench flags use the non-selective classical reference search. Timing
can prioritize the next candidate; adoption still requires the two SPRT stages
under the retained playing settings. Neither node savings nor a timing sign test
establishes an Elo gain. Every output directory must be new.

The `Direct Legal Moves` candidate exposes `--direct-legal` to the same bench
tool. It must preserve the full reference work signature, so use fixed-work
mode. After freezing the verified candidate and waiting for the lease to be free:

```sh
python3 tools/performance.py --baseline artifacts/checkpoints/orient-012-direct-legal/orient --candidate artifacts/checkpoints/orient-012-direct-legal/orient --candidate-argument=--direct-legal --depth 6 --pairs 10 --out artifacts/performance/direct-legal-001
```

Repeatable `--baseline-argument`/`--candidate-argument` flags can enable
`--fast-quiescence` equally on both sides for a later combined-path measurement.
Keep each experiment's changed setting explicit and retain its own evidence.

## Analysis and acceptance

### Interrupted development recovery

`tools/recover_dev.py` continues a stopped confirmation in a new output directory,
retaining its accepted short stage, every audited complete batch and every
complete game in the partial PGN. The supported partial shape is a contiguous
prefix of complete reversed-colour pairs. One-sided or ambiguous prefixes fail
closed rather than dropping games. Partial PGNs can contain a completed game
whose stdout finish line was not flushed: starts and all present finish events
must agree with the PGN, and the discrepancy is recorded explicitly.

First run a no-game preflight, using the saved host process-absence observation:

```sh
python3 tools/recover_dev.py --source artifacts/matches/null-move-003 --observation artifacts/investigations/session-loss-001/observation.json --out artifacts/investigations/session-loss-001/new-preflight --preflight
```

Actual execution additionally requires `--controller-checkpoint` pointing to
a frozen checkpoint containing exactly the loaded recovery, batch, support and
calculator sources. It preserves the original engines/options, opening sequence,
SPRT calibration, decision boundaries and 20,000-game cap. Only the missing suffix
is executed. Its actual command and raw PGN stay separate from the logical full
batch schedule and original prefix. The derived full PGN changes only the new
suffix's Round headers. Each recovered batch is reconstructed and checked before
its cumulative decision, and again before the final stage verdict. Signals trigger
owned-runner cleanup; designated child descriptors retain the compute guard.

For Null Move 003 the source partial log has 37 finish events, while the PGN
contains 38 complete games (19 complete pairs). Preflight retains all 38 and
schedules only the remaining 26 games of that batch. Neither the interruption
nor this recovery certifies an improvement. The original files stay immutable.

Use a transient user service with a process-scoped sleep inhibitor for long
continuations. Preserve its exact launch arguments, unit identity, process state
and project-local logs. Check the actual service/process state; stale session
handles or the presence of a lock file do not prove a job is running. This adds
no recurring automation or permanent power configuration.

`rating.py` re-hashes every frozen binary, source archive, command, opening slice, log and PGN. It checks all six exact opponent identities, reconstructed runner arguments, PGN time controls and exactly 500 complete reversed pairs per opponent. Incomplete counts, unexpected positions, duplicate colour games, altered files or failed runner exits are rejected. Crashes, illegal moves, time forfeits and other reliability diagnostics are included as failures. Warnings from an unsupported optional Ponder UCI setting are avoided through the frozen handshake.

The point estimate fits a logistic expected-score model against all six anchors. Confidence intervals resample complete opening pairs within each opponent group, preserving the dependence between reversed games. A second interval propagates the published reference error as independent Gaussian uncertainty (`sigma = 95% half-width / 1.959964`). The report includes both intervals, leave-one-opponent-out fits, W–D–L totals, seeds and hardware information. All-win/all-loss saturated samples are unidentifiable and cannot pass the goal. The implementation rejects manufactured zero-width bootstrap claims for those samples.

A leave-one-opponent-out subset can be all wins or all losses even when the whole
campaign has a finite estimate. Such sensitivity entries are explicitly unbounded;
they do not prevent preserving the complete overall report. PGN starting clocks
must match the frozen EPD defaults of `0 1`, as well as matching the board, side,
castling and en-passant fields.

The goal passes only when the complete 6,000-game campaign has no reliability failure and the lower endpoint of the reference-error-propagated 95% interval is at least 3000. Intervals do not account for unknown correlated anchor errors, hardware transfer, opening-distribution transfer or selection of an unusually successful campaign. Publish all completed attempts rather than repeatedly testing and reporting only the best. A published independent rating remains a separate future accomplishment.

Run tooling checks with `python3 tests/test_tools.py`. Synthetic fixtures exercise the full 6,000-game audit, altered hashes, incomplete counts, forfeits, rating recovery, paired uncertainty, degenerate results, exact snapshot parsing, option isolation, development-stage artifact changes and self-play setting mismatches. Synthetic scores are test data and must never be presented as measured Orient playing strength.

Development SPRTs require original source checkpoints for both sides, defaulting
to `checkpoint.json` beside each executable. The controller saves its own source
and statistics helper, probes supported UCI options, and checks binaries, source,
openings, runner and any learned weights before and after each stage. A change in
those artifacts fails the experiment rather than retaining its score. The first
Null Move run predates these additional checks and was stopped for a confirmed
baseline correctness defect after 528 games. Its saved source, result, stop request,
PGN and separate correctness review remain preserved; no improvement was retained.

When a side enables `Use NNUE=true`, pass `--candidate-network-manifest` or
`--baseline-network-manifest` with its original `network.json`. The matching
`EvalFile` is recorded automatically. Imported labels, missing ancestry and
unverified exports are rejected. The same candidate-manifest flag applies to
bounded pilots. This preparation does not make a network a retained improvement.
